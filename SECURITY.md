# Security Policy

## Supported versions

Security fixes are prioritized for the current maintained version of Yamandu Native AI Content Creator. Users should update to the latest available release before reporting an issue that may already have been fixed.

## Reporting a vulnerability

Please do not open a public GitHub issue for a suspected security vulnerability.

When GitHub private vulnerability reporting is available for this repository, use the **Security** tab and choose **Report a vulnerability** so the report can be handled privately.

If private vulnerability reporting is not available, contact Rede Piabanha through the official website at https://piabanha.net/ and indicate that the message concerns a security vulnerability in Yamandu Native AI Content Creator. Do not include secrets, API keys, credentials, personal data, or exploit details in a public channel.

Please include, when possible:

- the affected Yamandu version;
- the WordPress and PHP versions;
- a clear description of the vulnerability;
- steps to reproduce it;
- the expected and actual behavior;
- the potential security impact;
- any suggested mitigation or patch.

We ask reporters to allow a reasonable period for investigation and remediation before public disclosure.

## Scope

Security reports may include issues involving authentication, authorization, privilege escalation, unsafe handling of API credentials, cross-site scripting, cross-site request forgery, SQL injection, remote code execution, arbitrary file access, sensitive-data exposure, insecure external requests, and other vulnerabilities that can materially affect WordPress sites using the plugin.

Third-party services and bundled components remain subject to their own security policies. Vulnerabilities that originate solely in a third-party dependency should also be reported to that project's maintainers when appropriate.
